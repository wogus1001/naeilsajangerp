# Franchise UI Redesign Plan

## 목적

프랜차이즈 본사 임직원이 매일 사용하는 화면을 더 간결하고 빠르게 판단 가능한 업무 도구로 개편한다. 목표는 기능을 줄이는 것이 아니라, 사용자가 지금 해야 할 일과 다음 행동을 더 빨리 찾게 만드는 것이다.

디자인 톤은 토스처럼 깔끔하고 간결한 업무형 UI를 지향한다. 특정 서비스를 복제하지 않고, 아래 원칙을 우리 제품에 맞게 적용한다.

- 흰 배경과 낮은 대비의 회색 면을 기본으로 사용한다.
- 장식용 그라데이션, 큰 그림자, 과한 pill, 과한 볼드 텍스트를 줄인다.
- 한 화면에서 가장 중요한 행동을 1개만 강하게 보여준다.
- 설명문은 짧게 줄이고, 필요한 맥락은 툴팁이나 접힘 영역으로 보낸다.
- 카드보다 표, 리스트, 보드, 사이드 패널을 우선한다.
- 데이터가 많은 화면은 `요약 -> 필터 -> 목록 -> 상세`의 예측 가능한 구조로 통일한다.

## 2026-06-11 UI 감사 요약

검토 화면:

- `/dashboard/franchise-leads`
- `/dashboard/franchise-leads/market-insights?tab=realty-import`
- `/dashboard/franchise-operations`
- 모바일 390px 운영 화면

현재 좋은 점:

- 핵심 프랜차이즈 업무 흐름은 이미 연결되어 있다.
- 1차 유입 DB, 후보자, 후보지, 외부 상가, 정보공개서, 오픈 준비 프로젝트의 기능 축이 명확하다.
- 모바일 전역 사이드바 접힘과 기본 overflow 대응은 개선되어 있다.
- 본사 직원이 실제로 처리해야 할 업무 데이터가 화면에 충분히 있다.

현재 문제:

- 한 화면에 카드, 배지, 버튼, 설명문, 그래프, 표가 동시에 많아 첫 시선이 분산된다.
- `font-weight: 850~950`, pill, 그림자, 둥근 카드, 그라데이션이 많이 반복되어 AI가 덧붙인 듯한 장식감이 난다.
- 등록 폼이 업무 현황보다 먼저 보이는 화면이 있어, 매일 사용하는 직원 입장에서 우선순위가 뒤집힌다.
- 외부 상가 화면은 저장 지역 칩과 필터가 많아질수록 상단을 과하게 점유한다.
- 화면별 CSS가 `page.module.css`에 크게 누적되어 디자인 규칙을 일관되게 바꾸기 어렵다.
- 안내 문구가 기능 설명 중심이라, 사용자의 다음 행동을 짧게 안내하는 문장으로 정리할 필요가 있다.

## 디자인 방향

### 톤

차분한 본사 업무용 SaaS. 마케팅 페이지처럼 보여서는 안 된다.

목표 인상:

- 신뢰감
- 빠른 판단
- 적은 장식
- 높은 가독성
- 실무자가 반복 사용해도 피로하지 않은 화면

피해야 할 인상:

- AI가 만든 대시보드처럼 과한 카드와 배지
- 보라/민트 그라데이션 반복
- 모든 숫자가 KPI처럼 강조되는 화면
- 각 섹션이 독립 랜딩 페이지처럼 보이는 구조

### 색상

권장 팔레트:

- 배경: `#F7F8FA`
- 표면: `#FFFFFF`
- 주요 텍스트: `#191F28`
- 보조 텍스트: `#6B7684`
- 약한 텍스트: `#8B95A1`
- 경계선: `#E5E8EB`
- 주 액션: `#3182F6`
- 성공: `#00A66A`
- 주의: `#F59E0B`
- 위험: `#E5484D`

운영 원칙:

- 파란색은 주요 CTA와 현재 선택 상태에만 사용한다.
- 상태 색은 작은 배지나 아이콘에만 사용한다.
- 섹션 배경에 그라데이션을 쓰지 않는다.
- 그림자는 모달, 드롭다운, floating panel에만 제한한다.

### 타이포그래피

- Pretendard 유지.
- 제목은 과하게 크지 않게 한다.
- 본문과 표는 13~14px 중심으로 맞춘다.
- `font-weight: 900` 계열은 숫자 핵심값과 아주 중요한 제목에만 제한한다.
- letter-spacing 음수는 제거한다.

### 레이아웃

공통 화면 구조:

1. Page header: 페이지명, 짧은 설명, 주요 CTA 1개
2. Work summary: 오늘 해야 할 일과 위험/지연 요약
3. Primary workspace: 리스트, 표, 칸반, 지도 중 하나
4. Detail panel: 선택한 항목 상세와 수정
5. Secondary tools: 업로드, 연동, 설정, 고급 필터

섹션 규칙:

- 반복 카드 안에 또 카드를 넣지 않는다.
- 큰 섹션은 카드보다 full-width band 또는 단순 컨테이너로 둔다.
- 표/리스트는 선과 여백으로 구분하고 그림자는 쓰지 않는다.
- 설정/등록 폼은 기본 화면에 항상 펼치지 않고 `새로 만들기`, `편집` 액션 후 사이드 패널이나 모달로 연다.

## 화면별 개편 방향

### 1. 모객 DB

현재 문제:

- 상단에 CTA가 많다.
- KPI 카드가 많아 실제로 오늘 처리할 업무보다 숫자 전시가 먼저 보인다.
- 대시보드와 DB 관리 전환은 좋지만, 정보 밀도와 우선순위가 섞인다.

개편 방향:

- 상단 CTA는 `후보자 등록` 1개만 primary로 둔다.
- `엑셀 업로드`, `Meta 연동`, `샘플 양식`은 secondary menu로 묶는다.
- 첫 화면은 `오늘 처리할 리드`, `연락 지연`, `무응답`, `계약 차단/가능` 중심으로 바꾼다.
- KPI 카드는 3~4개로 줄이고 나머지는 리포트 탭으로 이동한다.
- 후보자 상세는 오른쪽 drawer로 통일하고, 업무/후보지/정보공개서를 탭으로 정리한다.

권장 첫 화면:

- 좌측: 업무 큐 리스트
- 중앙: 후보자 목록
- 우측 drawer: 선택 후보자 상세

2026-06-11 1차 반영:

- 상단 CTA는 데스크톱에서는 기존 기능을 유지하되, 모바일에서는 `후보자 등록`만 남기고 Meta/엑셀/샘플 양식 보조 액션을 숨겼다.
- 기간 필터는 `7D/30D/3M` 대신 `최근 7일/최근 30일/최근 3개월`로 바꿨고, 필터 아이콘과 중복 빠른 필터를 제거했다.
- 등록일 기간 입력 사이에 `~` 구분자를 추가하고 select 화살표 여백을 보정했다.
- KPI와 그래프는 `1차 유입 DB -> 후보자 -> 상담 진행` 흐름에 맞춰 정리했고, `최근 유입`을 `일별/주별/월별 DB 유입` 전환 그래프로 바꿨다.
- `담당자별 모객` 그래프를 추가해 본사 직원별 담당 수를 볼 수 있게 했다.
- 모바일에서는 파이프라인 단계 선택 카드 묶음을 숨겨 대시보드 첫 화면의 세로 점유를 줄였다.
- 후보자 등록 폼은 연락처 자동 하이픈 포맷과 시도/시군구 다중 희망지역 선택으로 바꿔 DB 관리 단계의 후처리를 줄였다.
- `DB 관리`는 별도 workspace 컴포넌트로 분리하고, 표시 컬럼 선택/지역 OR 검색/예산 범위 필터/등록순/예산순/중요 희망자 정렬을 추가했다.
- 고객 강조 표현은 `핵심` 대신 `중요`로 통일했다. 별표는 중요 희망자 표시로만 쓰고, 테이블 기본 문구와 정렬 옵션도 `중요` 기준으로 맞춘다.

### 2. 외부 상가 수집

현재 문제:

- 수집 폼, 수집 결과, 저장 지역 칩, 필터, 동 카드, 지도, 표가 한 화면에 길게 이어진다.
- 저장 지역이 많아지면 칩이 화면을 과하게 차지한다.
- 사용자가 먼저 해야 할 일이 `수집`, `검토`, `승격`, `운영전환` 중 무엇인지 즉시 보이지 않는다.

개편 방향:

- 상단은 `지역 선택 + 수집 실행`만 남긴다.
- 저장 지역 칩은 검색 가능한 dropdown 또는 좌측 narrow list로 바꾼다.
- 기본 목록은 `추천순 상위 후보`를 먼저 보여준다.
- 지도는 항상 펼치지 않고 `지도 보기` 토글로 연다.
- 동 카드 accordion은 유지하되, 기본은 선택 지역의 추천 후보 목록으로 시작한다.
- `물건지 등록`, `승격됨`, `운영점 등록 대기` 상태를 하나의 단계형 badge로 통일한다.

권장 첫 화면:

- 상단: 지역 선택, 수집 실행, 최신화
- 본문 좌측: 저장 지역/필터
- 본문 중앙: 추천 후보 표
- 우측 drawer: 선택 매물 상세, 승격/운영전환 action

### 3. 가맹 운영

현재 문제:

- 등록 폼이 운영 현황보다 먼저 큰 공간을 차지한다.
- 매일 보는 본사 직원에게 중요한 것은 신규 등록보다 지연 프로젝트, 오픈 예정, 운영 이슈다.

개편 방향:

- 첫 화면은 `오픈 준비`, `운영중`, `휴점/이슈`, `점검 필요` 요약으로 시작한다.
- `새 가맹점`은 primary CTA지만 폼은 drawer로 연다.
- 오픈 준비 프로젝트는 칸반 또는 단계형 보드로 올린다.
- 운영점 목록과 프로젝트 목록을 분리하지 말고, 운영점 기준으로 상태/다음 할 일을 같이 보여준다.

권장 첫 화면:

- 상단: 운영 요약과 지연 알림
- 중앙: 오픈 준비 프로젝트 보드
- 하단/탭: 운영점 마스터 목록
- 우측 drawer: 운영점 상세/등록/수정

### 4. 정보공개서/계약 컴플라이언스

현재 문제:

- 기능은 맞지만 후보자 상세 안에서 다른 기능과 같은 밀도로 보여지면 중요도가 묻힐 수 있다.

개편 방향:

- 후보자 상세 상단에 계약 가능 상태를 명확히 표시한다.
- `발송 전`, `D-14`, `계약 가능`, `계약 차단`을 같은 컴포넌트로 통일한다.
- 정보공개서 발송은 독립 action으로 보이고, 발송 이력은 audit timeline으로 정리한다.
- 향후 이메일/알림톡 자동발송은 발송 로그 중심으로 설계한다.

## QA 기준

각 phase는 다음 기준을 통과해야 한다.

- 390px 모바일에서 가로 overflow 0
- 1440px 데스크톱에서 첫 화면 핵심 CTA와 핵심 상태가 보임
- 버튼 텍스트가 줄바꿈으로 깨지지 않음
- 표는 최소 폭과 가로 스크롤 정책이 명확함
- 모달/drawer에서 focus와 닫기 동작이 일관됨
- 기존 기능 저장/새로고침 persistence 유지
- `npx tsc --noEmit`, `npm run lint -- --quiet`, `npm run build` 통과
- Playwright로 주요 화면 visual QA 수행

## 다음 개발 추천
