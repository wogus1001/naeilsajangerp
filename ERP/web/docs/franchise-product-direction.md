# Franchise Product Direction

## 목적

프랜차이즈 본사 임직원이 매일 사용하는 통합 운영 솔루션의 거시 개발 방향을 정리한다. 세부 기능 우선순위와 QA 상태는 `franchise-growth-roadmap.md`, `franchise-dev-qa-log.md`에서 관리하고, 이 문서는 제품 판단 기준과 장기 구조를 관리한다.

## 제품 정의

우리는 단순 CRM이나 점포 DB가 아니라 프랜차이즈 본사용 운영 OS를 만든다.

핵심 흐름은 다음과 같다.

1. 모객 유입과 1차 DB 정리
2. 후보자 승격, 상담, 업무 큐, 담당자 성과 관리
3. 정보공개서 제공, 계약 전 컴플라이언스, 계약 준비
4. 후보지, 외부 상가, 상권, 경쟁환경 검토
5. 오픈 준비 프로젝트와 운영점 전환
6. 운영점 마스터, SV 방문, QSCV, CS, 공지, 교육
7. 리뷰, 매출, 물류, 정산, 로열티 리포팅

첫 번째 사용자는 프랜차이즈 본사 임직원이다. 가맹점주용 포털이나 앱은 본사 운영 데이터 구조가 안정된 뒤 확장한다.

## 레퍼런스에서 얻은 제품 원칙

### FDAM

프담은 가맹 영업관리, 계약, 매장 오픈관리, 운영관리, QSCV, CS를 프랜차이즈 본사 흐름으로 연결한다. 우리 제품도 화면 단위 기능을 늘리는 것보다 `영업 -> 계약 -> 오픈 -> 운영` 데이터 흐름을 끊기지 않게 만드는 것이 우선이다.

상세 분석은 `fdam-reference.md`를 기준으로 한다.

### LeadPlanet

리드플래닛은 가맹점 품질관리, 가맹점 앱, POS 연동, 방문 실적, 교육 관리처럼 오픈 이후 운영 데이터에 강점이 있다. 우리 제품은 P0/P1에서 영업과 오픈 전환을 안정화한 뒤, 운영점 마스터와 SV/QSCV/교육을 다음 큰 축으로 잡는다.

### FranConnect

FranConnect는 리드, 오픈, 운영, 품질, 성과, 로열티를 성장 여정으로 묶는다. 우리 제품도 특정 부서 도구가 아니라 본사 성장 여정을 관리하는 시스템이어야 한다.

### ClientTether

ClientTether는 리드 응답 속도, 멀티채널 커뮤니케이션, 자동화, 리포팅을 강조한다. 우리 모객 DB의 업무 큐는 단순 목록이 아니라 응답 지연, 무응답, 오늘 연락, 담당자 처리율을 강하게 보여줘야 한다.

### SiteZeus / Zors AI

상권, 후보지, 권역, POI, CRM을 지도 기반으로 연결한다. 우리 제품은 후보자 희망지역, 예산, 브랜드, 후보지, 외부 상가, 경쟁스캔을 같은 의사결정 화면에서 이어야 한다.

### Zenput

운영점 체크리스트, 현장 업무, 브랜드 표준 준수, 시정 조치가 핵심이다. 오픈 이후 확장은 QSCV 폼 빌더, 방문 일정, 점검 결과, 시정조치 업무로 시작한다.

### SOCi

다점포 로컬 마케팅, 리뷰, 검색 노출, 위치별 고객 응대 자동화가 핵심이다. 우리 제품은 초기에는 리뷰/검색 노출을 수동 또는 CSV/import 중심으로 받고, 이후 AI 답글과 지역별 평판 리포트로 확장한다.

## 한국 프랜차이즈 컴플라이언스 원칙

정보공개서 기능은 계약 부속 기능이 아니라 제품의 핵심 리스크 관리 기능이다.

- 등록 또는 변경등록한 정보공개서를 제공해야 한다.
- 정보공개서 제공시점을 객관적으로 확인할 수 있어야 한다.
- 제공 후 14일이 지나지 않으면 가맹계약 체결 또는 가맹금 수령을 막아야 한다.
- 변호사 또는 가맹거래사 자문 예외로 7일 기준이 적용되는 경우는 별도 증빙과 정책 확인 후 구현한다.
- 정보공개서 제공 시 인근가맹점 현황문서 제공 여부도 장기적으로 관리해야 한다.
- 예상수익, 상권분석, 지원조건 등 허위ㆍ과장 정보 제공 리스크를 줄이기 위해 상담/자료 제공 이력을 남겨야 한다.

## 개발 방향

### 1. Lead Command Center

모객 DB는 모든 성장 흐름의 시작점이다.

중점 기능:

- 1차 유입 DB와 후보자 분리 유지
- 업무 큐 2.0: 연락 지연, 오늘 연락, 무응답, 담당자별 병목
- 상담 이력, 다음 액션, 이탈 사유, 적합도 관리
- 소스별 전환율, 응답 속도, 담당자 처리율
- Meta Lead Ads는 env와 계정 문제가 풀릴 때까지 HOLD

### 2. Compliance-First Contract Pipeline

계약 단계는 정보공개서와 감사 로그가 선행되어야 한다.

중점 기능:

- 회사별 정보공개서 문서함
- 후보자별 발송 이력과 최신 문서 버전 고정
- 계약 가능일 자동 계산과 서버 차단
- 이메일/카카오 알림톡 자동발송 로그
- 인근가맹점 현황문서, 계약서 템플릿, 전자계약 연결

### 3. Site And Market Pipeline

후보자와 후보지를 분리된 화면으로만 두지 않고, 오픈 가능성 판단에 필요한 데이터를 연결한다.

중점 기능:

- 후보자 희망지역/예산/브랜드와 출점 후보지 연결
- 외부 상가 저장 목록, 수동 승격, 운영 전환 유지
- 경쟁환경 스캔 캐시와 provider 상태 분리
- 업종별 예산/면적/입지 규칙 기반 추천점수
- 권역 중복, 주변 운영점, 경쟁사 밀도 표시

### 4. Opening Project OS

계약 후 오픈까지의 업무를 별도 프로젝트로 관리한다.

중점 기능:

- 오픈준비 운영점별 프로젝트
- 계약, 인테리어, 교육, 초도물류, 홍보, 오픈일 checklist
- 목표 오픈일, 지연 사유, 담당자, 변경 이력
- 칸반 또는 단계형 보드
- 운영점 마스터 전환 시 source property와 후보자 연결 유지

### 5. Store Master And Operations

오픈 이후의 기준 데이터는 운영점 마스터다.

중점 기능:

- 브랜드, 점주, 사업자번호, 계약일, 오픈일, 운영상태
- SV 담당자, 지역팀, 운영 유형, 물류사, 채널 연결 상태
- 운영점 상세에서 계약, 점검, CS, 리뷰, 매출 요약 연결
- 직영점, 가맹점, 오픈준비, 휴점, 폐점 상태 관리

### 6. QSCV / SV / CS Execution

본사 운영팀이 매일 쓰는 현장 실행 기능이다.

중점 기능:

- 방문 일정과 방문 목적
- QSCV 폼 빌더
- 점검 결과와 점수
- 시정조치 업무, 담당자, 기한, 상태
- CS 티켓과 처리 이력
- 공지/매뉴얼 배포 및 읽음 확인

### 7. Performance, Reviews, Sales, Logistics

외부 연동 의존도가 크므로 CSV/import 기반부터 시작한다.

중점 기능:

- POS/배달앱/물류 CSV import
- 운영점별 매출, 주문채널, 메뉴, 물류 매출 비교
- 리뷰 import, 위험 키워드, 답글 템플릿
- 브랜드/지역/운영담당자별 리포트
- 이후 공식 연동과 AI 요약/답글 자동화

## 단계별 우선순위

### P0: 현재 핵심 흐름 안정화

- 실운영 계정 role matrix QA
- SearchAPI quota/provider 상태 보호
- 오픈 준비 프로젝트 UI 저장 후 새로고침 persistence
- 정보공개서 발송 이력과 계약 잠금 회귀
- 기존 외부 상가 자동 등록 금지 회귀

### P1: 본사 직원 Daily Workspace

- 업무 큐 2.0
- 계약 가능/계약 차단 리드 보드
- 오픈 프로젝트 칸반
- 지연 업무/담당자별 병목 알림
- 회사별 마스터 코드 설정

### P2: Store Master 강화

- 운영점 상세 고도화
- 오픈 프로젝트에서 운영점 전환 이력
- SV/지역팀/운영상태 관리
- 운영점 기준 계약, 후보자, 물건지, 점검 연결

### P3: QSCV/SV/CS MVP

- 방문 일정
- 점검 폼
- 점검 결과
- 시정조치
- CS 티켓

### P4: 리뷰/매출/물류 데이터

- CSV/import 기반 수집
- 리뷰 위험 키워드
- 운영점별 매출/물류 리포트
- 브랜드/지역별 성과 비교

### P5: 자동화와 AI

- 이메일/카카오 알림톡 자동발송
- 리드 응답 자동화
- 후보지 추천
- 리뷰 답글 초안
- QSCV 리스크 요약

## 설계 원칙

- 본사 임직원의 실제 업무 순서를 먼저 맞춘다.
- 가맹점주 포털보다 본사 내부 운영 데이터 구조를 먼저 안정화한다.
- 외부 API는 provider 상태, quota, timeout, 결과 없음 상태를 분리한다.
- 법적 리스크가 있는 단계는 서버에서 차단하고 감사 로그를 남긴다.
- 모든 확장 기능은 회사 범위와 권한 범위를 기본 전제로 둔다.
- 자동화는 수동 업무 흐름이 검증된 뒤 붙인다.
- POS, 배달앱, 물류 연동은 CSV/import를 먼저 만들고 실시간 연동은 후순위로 둔다.
